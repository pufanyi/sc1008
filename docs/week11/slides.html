Question 2: Copy Constructor

Identifying issues in the VisitorCounter class

The Code


#include <iostream>
using namespace std;

class VisitorCounter {
private:
    int* count; // Pointer to dynamically allocated memory

public:
    VisitorCounter(int initialCount) {
        count = new int(initialCount);
        cout << "Constructor called with the count as "
             << *count << endl;
    }

    ~VisitorCounter() {
        cout << "Destructor called with the count being "
             << *count << endl;
        delete count;
    }

    void increment() { (*count)++; }

    void display() const {
        cout << "Visitor Count: " << *count << endl;
    }
};

The Test Code


int main() {
    VisitorCounter counter(10);
    cout << "\nOriginal Counter:\n";
    counter.display();

    // Copy the counter
    VisitorCounter counterCopy = counter;
    cout << "counterCopy:\n";
    counterCopy.display();

    // Increase copied object's count
    counterCopy.increment();
    counterCopy.increment();
    cout << "\nAfter modifying copied counter...\n";
    cout << "Original Counter: " << endl;
    counter.display();
    cout << "counterCopy: " << endl;
    counterCopy.display();

    return 0;
}

What Goes Wrong?

No copy constructor defined → compiler generates a default one


// Compiler-generated default copy constructor:
VisitorCounter(const VisitorCounter& other) {
    count = other.count;  // Copies the POINTER, not the data!
}

This is a shallow copy — both objects share the same memory

Issue 1: Unintended Sharing


counterCopy.increment();  // (*count)++ → 11
counterCopy.increment();  // (*count)++ → 12

counter.display() also prints 12!
Modifying the copy unexpectedly changes the original.

Issue 2: Double Free

When main() ends, destructors run in reverse order:

1 counterCopy destructor: delete count; — frees 0xA00 ✓

2 counter destructor: delete count; — frees 0xA00 again!

Undefined Behavior!
Double free can cause crashes, memory corruption, or security vulnerabilities

Summary of Issues

  1. Shallow Copy — default copy constructor copies the pointer, not the pointed-to data
  2. Unintended Sharing — modifying one object affects the other
  3. Double Free — both destructors delete the same memory
  4. No Copy Assignment Operator — a = b; would have the same issues

The Fix: Deep Copy Constructor


VisitorCounter(const VisitorCounter& other) {
    count = new int(*other.count);  // Allocate NEW memory
    cout << "Copy constructor called with count "
         << *count << endl;
}
Stack
counter
count: 0xA00
counterCopy
count: 0xB00
Heap
0xA00
10
0xB00
10

Each object owns its own memory — independent and safe!

Also Fix: Copy Assignment Operator


VisitorCounter& operator=(const VisitorCounter& other) {
    if (this != &other) {          // Self-assignment check
        *count = *other.count;     // Copy the VALUE
    }
    return *this;
}

Without this, a = b; would still cause shallow copy issues

The Rule of Three

If a class needs any one of these, it probably needs all three:

1 Destructor — clean up resources

2 Copy Constructor — deep copy on initialization

3 Copy Assignment Operator — deep copy on assignment

If your class manages a resource (heap memory, file handle, etc.), you need all three!

Complete Fixed Class


class VisitorCounter {
private:
    int* count;

public:
    // Constructor
    VisitorCounter(int initialCount) {
        count = new int(initialCount);
        cout << "Constructor called with the count as "
             << *count << endl;
    }

    // Copy Constructor (DEEP COPY)
    VisitorCounter(const VisitorCounter& other) {
        count = new int(*other.count);
        cout << "Copy constructor called with count "
             << *count << endl;
    }

    // Copy Assignment Operator
    VisitorCounter& operator=(const VisitorCounter& other) {
        if (this != &other) {
            *count = *other.count;
        }
        return *this;
    }

    // Destructor
    ~VisitorCounter() {
        cout << "Destructor called with the count being "
             << *count << endl;
        delete count;
    }

    void increment() { (*count)++; }
    void display() const {
        cout << "Visitor Count: " << *count << endl;
    }
};

Shallow Copy vs Deep Copy

Shallow Copy Deep Copy
Pointer Copies pointer value Allocates new memory
Data Shared between objects Independent copies
Modify copy Affects original No side effects
Destruction Double free! Safe cleanup

Key Takeaways

  • Default copy constructor does shallow copy — fine for simple types, dangerous for pointers
  • If your class uses new, you need a deep copy constructor
  • Remember the Rule of Three: destructor + copy constructor + copy assignment
  • Always test: does copying an object cause unexpected sharing or crashes?
