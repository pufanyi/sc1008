Step (v)

ref = &num2;

error: invalid conversion from 'int*' to 'int'
   ref = &num2;
         ^~~~~
         |

&num2 is of type int*, but ref is int& (alias for an int)

Cannot assign a pointer to an integer without explicit cast

This would compile in C (with warning), but NOT in C++

Summary

Step Operation num1 num2 p *p ref &ref p →
init 100 200 8800 100 100 8800 num1
(i) *p = 50 50 200 8800 50 50 8800 num1
(ii) ref = ref / 2 25 200 8800 25 25 8800 num1
(iii) p=&num2; *p=400 25 400 9976 400 25 8800 num2
(iv) ref=num2; ref*=2 800 400 9976 400 800 8800 num2
(v) ref = &num2 Compilation Error: invalid conversion from int* to int

Key Takeaways

  • int &ref = *p — ref binds to the variable p points to
  • References cannot be rebound — ref always aliases num1
  • ref = x modifies num1, not the reference itself
  • &ref always returns &num1 (8800)
  • Changing p does NOT affect what ref refers to
  • Pointer vs Reference: pointers can be reassigned, references cannot
  • ref = &var — compilation error! Cannot assign int* to int&

Why avoid using namespace std;?

For this course it's fine, but good to know for the future

Name Collision


#include <algorithm>
using namespace std;

int count = 0;  // Conflicts with std::count!

std has thousands of names: count, find, sort, distance, map, array, ...

Your variable names may silently shadow or conflict with them

The Real Danger: Headers


// mylib.hpp
#include <vector>
using namespace std;  // This pollutes EVERY file
                      // that #includes mylib.hpp!

class vector { ... }; // Now ambiguous with std::vector

Anyone who #include "mylib.hpp" is forced into using namespace std

They can't opt out — you've polluted their namespace

What to Do Instead


// Option 1: Prefix with std::
std::cout << "Hello" << std::endl;
std::vector<int> v;

// Option 2: Import only what you need
using std::cout;
using std::endl;
using std::vector;

A few extra characters, but avoids all the problems

Summary

  • In .cpp files for small projects / coursework — OK to use
  • In .hpp / header files — never use it
  • In production / team projects — avoid it
  • Best practice: always use std:: prefix
